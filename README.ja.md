# aib

**複数の AI を 1 つの作業空間で：どのベンダーの AI ツールも無料で取り込み、席ごとに人格・専門性・プロジェクト記憶を持たせ、
突然の切断のあとでも、どの AI でも前の AI の続きから作業を引き継げます。**

- **どのベンダーの AI も無料で取り込めます。** aib は無料のオープンソース<sup>[1]</sup>です。AI コーディングツール<sup>[2]</sup>、
  API キー<sup>[3]</sup>で使うモデル<sup>[4]</sup>、デスクトップ AI アプリ（Claude、Codex Desktop など）は、
  どれも連携して働く席<sup>[5]</sup>として開けます。各 AI はあなた自身のアカウントやキーを使い、aib が追加料金を取ることはありません。
- **aib ごとにコックピット<sup>[6]</sup>があり、コックピットごとに席があります。** コックピットは 1 つの tmux<sup>[7]</sup> ウィンドウで、
  複数の AI の席が並び、それぞれに役割（`dev`、`qa`、`pm` など）があります。席どうしでメッセージを送り合い、作業を受け渡します。
- **AI ごとに人格と専門性を持たせられます。** 各席には独自の人格<sup>[8]</sup>（第一の脳：性格、話し方、仕事の原則）と、
  独自の専門性（開発、テスト、企画など）を設定できます。
- **答えは 1 つではありません：異なるベンダーの AI が互いをチェックします。** 同じ質問を異なるベンダーの AI に渡すと、
  それぞれが答えたうえで互いにレビューし、弱点や盲点を指摘し合います。1 社の見方だけに縛られることはありません。
- **第二の脳<sup>[9]</sup>にいつでも書き込めます。** 開発や議論の途中でも、要点や決定事項を好きなときに第二の脳（プロジェクト記憶）に
  保存できます。切断やクラッシュがあっても何も失われません。長い会話で AI が混乱してきたら、席を開き直すだけで記憶がすぐに戻ります。
- **どの AI でも引き継げます。** 同じ席を今日は Claude、明日は Codex で動かしても、同じ人格と記憶を保てます。
  会話がいっぱいになると、次の担当者のために引き継ぎメモを残します。
- **価値ある会話を残し、AI のハルシネーション<sup>[10]</sup>を減らします。** 会話の中で残す価値のある要点は、人格と記憶の候補として
  抽出<sup>[11]</sup>され、あなたが承認すると書き込まれます。確認できる事実が書き残されているので、AI があいまいな記憶から推測することが減ります。
- **すべてあなたのマシンに残ります。** 席の記録、引き継ぎメモ、人格、プロジェクト記憶はすべてあなた自身のマシン
  （`~/.ez2-aib/`<sup>[12]</sup>）に保存され、アップロードされることはありません。

コックピットは macOS 上で tmux とともに動作します。1 つのコードベースで多くの AI が動けば変更も多くなるため、aib には
単独でも使える安全網も付属しています（Linux または macOS）：

- `aib test` は、変更の影響を受けるテスト<sup>[13]</sup>だけを再実行します（Python、bash、Node<sup>[14]</sup> を追跡）。それ以外は前回の
  **グリーン**<sup>[15]</sup>の結果を再利用します。レッドの結果は決して再利用せず、aib が計測できないものは必ず実行します。
- `aib ship` はプッシュ前チェック<sup>[16]</sup>です：新しいレッドがないパッケージだけがプッシュされます。リリースは、ターミナル<sup>[17]</sup>の前にいる
  人間だけが作成できます。

**注**
- [1] オープンソース：コードが公開されており、誰でも読み、使い、変更できることです。
- [2] AI コーディングツール：各ベンダーのコーディングアシスタントで、Claude Code（Anthropic）、Codex（OpenAI）、Antigravity（Google）、GitHub Copilot（GitHub）、Grok（xAI）などがあります。
- [3] API キー：AI サービスが発行する秘密の文字列で、プログラムがあなたの代わりにそのサービスを呼び出すために使います。
- [4] API キーで使うモデル：たとえば DeepSeek、OpenRouter（多くのモデルへの 1 つの入り口）、NVIDIA などです。
- [5] 席：コックピット内での 1 つの AI の居場所で、1 席に 1 つの AI がつき、それぞれ独自の役割と記憶を持ちます。
- [6] コックピット：aib が開く作業空間で、複数の席が並んでいます。
- [7] tmux：1 つのターミナルウィンドウを複数の区画に分割し、ウィンドウを閉じても動かし続けられるツールです。
- [8] 人格：席の性格、話し方、仕事の原則のことで、人格カードとして保存され、どの AI がその席を開いても読み込まれます。
- [9] 第二の脳：席のプロジェクト記憶で、あなた自身のマシンに保存されるメモの集まりです。
- [10] AI のハルシネーション：AI が誤った内容を、あたかも事実であるかのように述べることです。
- [11] 抽出：会話から残す価値のある要点を選び出し、ルールや知識にまとめることです。
- [12] `~/.ez2-aib/`：ホームフォルダ内のフォルダで、aib が記録を保存する場所です。
- [13] テスト：コードがまだ正しく動くかを自動で確認する小さなプログラムです。
- [14] Python、bash、Node：よく使われる 3 つのプログラミング言語／実行環境です。
- [15] グリーン／レッド：合格したテストはグリーン、不合格のテストはレッドです。
- [16] プッシュ前チェック：コードを共有バージョン（main ブランチ）にプッシュする前に、影響を受けるテストを実行することです。
- [17] ターミナル：文字でコマンドを入力するウィンドウです（macOS では「ターミナル」アプリ）。

## クイックスタート

```sh
curl -fsSL https://raw.githubusercontent.com/ez2app/ez2-aib/main/install.sh | bash
# 最新リリースを ~/ez2-aib にインストールします。同じ行をいつ再実行しても更新になります(Linux ではテストの安全網のみ。コックピットには macOS が必要です)
aib update                                          # aib のインストール後は同じことをこれで実行できます（aib update --tools では AI CLI の追加も提案します）
# その他の方法: pipx install ez2-aib    (pipx がない場合は macOS: brew install pipx / Linux: python3 -m pip install --user pipx、
#                                        続けて pipx ensurepath を実行し、新しいターミナルを開く)
#             git clone https://github.com/ez2app/ez2-aib ~/ez2-aib && export PATH="$HOME/ez2-aib/bin:$PATH"

cd your-project
aib claude safe dev                  # dev という名前の Claude Code の席を開きます（操作のたびに確認します）
aib codex safe qa                    # その隣に qa という名前の Codex の席を開きます
aib test tests/test_something.py     # 初回: 実行して記録します
aib test tests/test_something.py     # 何も変わっていない: 再利用します
aib test --all                       # スイート全体、同じルールで
aib ship package --branch my-branch  # プッシュ前チェックのあと、main にプッシュします
```

Linux または macOS 上の Python<sup>[18]</sup> 3.9 以上が必要です。コックピットには macOS と tmux が必要です。Windows はサポートしていません（WSL2<sup>[19]</sup> は未検証です）。
1 行目はワンライナーインストール<sup>[20]</sup>です。その他の方法では pipx<sup>[21]</sup>、git<sup>[22]</sup>、PATH<sup>[23]</sup> を使います。

**注**
- [18] Python：プログラミング言語の一つで、aib はこれで書かれているため、先にインストールしておく必要があります。
- [19] WSL2：Windows の中で Linux を動かす Windows の機能です。
- [20] ワンライナーインストール：`curl … | bash` でインストーラーをダウンロードし、そのまま実行することです。
- [21] pipx：Python のコマンドラインツールを、それぞれ互いに分離してインストールするツールです。
- [22] git：コードへのあらゆる変更を記録するツールで、`git clone` はコード一式のコピーをダウンロードします。
- [23] PATH：コンピューターがコマンドを探すフォルダの一覧で、フォルダを追加すると `aib` と入力できるようになります。

## コックピット：複数の AI を並べて

**コックピット**は、複数の AI コーディングアシスタント（「席」）を 1 つの tmux ウィンドウに並べて動かします。各席には
役割（`dev`、`qa`、`pm` など）があり、左／中央／右のレイアウト、マウスメニュー、席どうしのメッセージ、会話がいっぱいになったときの
引き継ぎメモ、フリートツール<sup>[24]</sup>（席の身元、作業の割り振り、巡回）を備えています。

```sh
aib claude safe dev        # dev という名前の Claude Code の席を開き、操作のたびに確認します
aib codex dgrs qa          # qa という名前の Codex の席を全許可モードで開きます（下記参照）
aib --help-cockpit         # すべてのオプション
```

- **必要なもの：** macOS と tmux。各 AI 自身のコマンドラインツール<sup>[25]</sup>（`claude`、`codex`、`grok` など）が、
  あらかじめインストールされログイン済みである必要があります。aib がインストールやログインを代行することはありません。コックピットはまだ Linux では試していません。
- **macOS での bash テスト：** aib が bash スクリプトを追跡するには bash 4.1 以降が必要です。macOS には bash 3.2 が付属しているため、bash スクリプトを
  実行するテストは「計測不可」と報告され、毎回再実行されます（安全ですが、遅くなります）。`brew install bash`<sup>[26]</sup> を実行すると再利用できるようになります。
- **権限モード（席ごと）：** `safe` は AI ツール本来の保護を維持します（ファイルの編集やコマンドの実行前に確認します）。
  `dgrs` はその保護を**その席に限って**オフにするため、AI は確認せずに操作します。aib は警告と、その席を `safe` で開き直すコマンドを表示します。
  どちらにするかは、席を開くときに席ごとに選べます。
- **Claude** は Anthropic の商標です。Codex は OpenAI の、Grok は xAI の商標です。aib はこれらの企業とは提携していません。

**注**
- [24] フリートツール：多くの席をまとめて管理する機能で、各席が誰か、作業の割り振り、定期的な巡回などを扱います。
- [25] コマンドラインツール：ターミナルでコマンドを入力して使うプログラムです（たとえば `claude`、`codex`）。
- [26] `brew install bash`：macOS でソフトウェアをインストールする一般的な方法である Homebrew で、新しい bash をインストールします。

## 予定：マシンやソーシャルチャネルをまたいで

> これらは予定段階で、まだ使えません。実装されしだい、それぞれ CHANGELOG<sup>[27]</sup> に記載します。

- **異なるマシン上の AI どうしが対話します。** すべての AI を 1 台のコンピューターに詰め込む必要はありません。自宅、職場、
  クラウドのホスト<sup>[28]</sup>にある AI の席どうしでメッセージを送り合えます。
- **自分のマシンから別のマシンの aib を操作します。** 自分のコンピューターの aib から、会話を通じて別のマシンの aib コックピットを操作したり、
  そのホスト上の aib にコマンドを送ったりできます。
- **ソーシャル会話の管理。** LINE、Telegram などのソーシャルプラットフォームの会話を取り込んで管理します。LINE と Telegram は
  社内テストですでに動作しており、今後公開する予定です。

**注**
- [27] CHANGELOG：各バージョンで何が追加・変更されたかの記録です。
- [28] ホスト：プログラムを動かすコンピューターのことで、ノートパソコン、オフィスのマシン、レンタルのクラウドサーバーなどがあります。

## 開発中：テストの高速化

> この部分はまだ開発中です。以下の数値や動作は変わる可能性があります。

aib は各テストがどのファイルを読んだかを記憶し、次回は変更の影響を受けるテストだけを再実行して、それ以外は前回のグリーンの
結果を再利用します。

**実測：aib 自身の開発**（2026-10-08〜10-10、プッシュ<sup>[29]</sup> 28 回、各回約 1,020 件のテスト）

| テストの実行方法 | 28 回のプッシュの合計 | プッシュ 1 回あたりの平均 | 1 件ずつ実行する場合と比べた削減 |
|---|---|---|---|
| aib なし、1 件ずつ実行<sup>[30]</sup> | 91.1 時間（約 3.8 日<sup>[31]</sup>） | 195 分 | （基準）91.1 時間 |
| aib あり、同じプロジェクトを 1 回で実行<sup>[32]</sup> | 43.8 時間（約 1.8 日） | 94 分 | 47.3 時間削減（約 2 日、52%） |
| **aib あり、同じプロジェクトを 3 分割して実行** | **16.6 時間（約 0.7 日）** | **36 分** | **74.5 時間削減（約 3.1 日）** |

- 91.1 時間から 43.8 時間への短縮は aib の再利用<sup>[33]</sup>によるものです：変更の影響を受けないテストは再実行しません。16.6 時間までの短縮は、残りのテストを 3 分割して同時に実行したことによるものです。
- 36 分はこの 28 回のプッシュの平均です。記録が蓄積されたあと、直近 10 回のプッシュの平均は約 18 分でした。
- 再利用が誤ることはあるのか：無作為に選んだ再利用済みテスト 13 件を実際に再実行したところ、13 件すべてが同じ結果となり、誤った再利用は 0 件でした。

**1 か月あたりの削減見込み**<sup>[34]</sup>

| テストの実行方法 | 1 か月あたりの目安 | 1 件ずつ実行する場合と比べた削減 |
|---|---|---|
| aib なし、1 件ずつ実行 | 395 時間（約 16.4 日） | （基準）395 時間 |
| aib あり、同じプロジェクトを 1 回で実行 | 190 時間（約 7.9 日） | 205 時間削減（約 8.5 日） |
| **aib あり、同じプロジェクトを 3 分割して実行** | **72 時間（約 3 日）** | **323 時間削減（約 13.5 日）** |

**小規模プロジェクト（Linux、4 コア）**

| プロジェクト | pytest<sup>[35]</sup> の並列実行 | aib の初回実行 | 2 回目以降の各回の削減 |
|---|---|---|---|
| [attrs](https://github.com/python-attrs/attrs)<sup>[36]</sup>（26 件のテスト） | 8.2 秒 | 15.1 秒 | 約 5 秒（変更なしの場合 3.0 秒） |
| [click](https://github.com/pallets/click)<sup>[37]</sup>（43 件のテスト） | 6.2 秒 | 17.2 秒 | 約 2 秒（変更なしの場合 3.8 秒） |

- 初回は各テストが読んだファイルを記録するため、pytest より遅くなります。2 回目以降は、影響を受けないテストが再利用されます。
- 「2 回目以降の各回の削減」は何も変更がない場合を想定しています。変更するファイルが多いほど再実行するテストが増え、削減は少なくなります。
- **向いている場合：** 数分以上かかるスイートで、変更のたびにその一部しか影響しない場合。**向いていない場合：** 数秒で終わるスイート。
- 副次的な効果：各テストが単独で実行されるため、別のテストが先に実行されたときにしか合格しないテストが明らかになります。

**注**
- [29] プッシュ：完成した変更を、全員が共有するバージョンに送ることです。
- [30] 1 件ずつ実行：91.1 時間は、aib のもとで計測した各テストの時間を合計した推定値で、追跡のオーバーヘッドを含むため高めに出ています。
- [31] 日：24 時間を 1 日として数えています（AI は昼夜を問わず動き続けられるため）。
- [32] 1 回で実行：aib は影響を受けるテストだけを 1 件ずつ順に実行し、43.8 時間はそれらのテストの実際の実行時間の合計です。
- [33] 再利用：テストが読んだファイルがどれも変更されていないため、再実行せずに前回のグリーンの結果を使うことです。
- [34] 1 か月あたりの削減見込み：実測したペース（週に約 28 回、月に約 121 回のプッシュ）× 52 ÷ 12 で見積もったもので、プッシュが少なければ削減も少なくなります。各プッシュでは 1 件ずつ実行する場合より約 160 分削減され、そのうち約 101 分は aib の再利用によるものです。
- [35] pytest：最も一般的な Python のテストツールで、すべてのテストを実行してどれが合格したかを報告します。「並列実行」は複数のプロセスを同時に動かす、最も速い実行モードです。
- [36] attrs：プログラマーが繰り返しのコードを書かずに済むようにする、よく知られたオープンソースの Python パッケージです。
- [37] click：コマンドラインツールを作るための、よく知られたオープンソースの Python パッケージです。

## 対応言語

Python（unittest<sup>[38]</sup>、pytest）は完全に追跡されます。Node（node:test、jest、mocha<sup>[39]</sup>）、Go、PHP<sup>[40]</sup> は
aib を通じて実行でき、プッシュ前チェックも受けられます。どれだけ再利用できるかはトレーサーが何を捉えられるかによります。最新の対応表は
`docs/AIB-TEST-QUICKSTART.ja.md` を参照してください。
その他の言語は `.aib/ship.toml` でテストコマンドを宣言できます。その場合は毎回実行されますが、パッケージングとリリースは利用できます。

**注**
- [38] unittest：Python に組み込まれたテストツールです。
- [39] node:test、jest、mocha：Node でよく使われる 3 つのテストツールです。
- [40] Go、PHP：ほかの 2 つのプログラミング言語です。

## 再利用はどのくらい安全か

- 再利用するのはグリーンの結果だけで、しかもテストが読んだすべての入力がバイト単位で同一の場合に限ります。
- テストが何を読んだかを aib が把握できない場合（追跡できないサブプロセス<sup>[41]</sup>、ネットワーク、自分でファイルを読むことが分かっている
  ネイティブ拡張）、そのテストは計測不可としてマークされ、必ず実行されます。
- **既知の抜け穴：** aib のリストに*載っていない* C 拡張<sup>[42]</sup>が C コードからファイルを読む場合、それは Python の
  監査フック<sup>[43]</sup>からは見えません。Linux では後述のネイティブ安全網がこれを捕捉しますが、**それがない場合（macOS、または C コンパイラ<sup>[44]</sup>がない場合）、
  そうしたファイルを変更しても再実行されないことがあります。** テストがそのように読まれるファイルに依存している場合は、リリース前に
  `aib test --fresh` を実行してください。
- `aib ship audit` は再利用されたテストから無作為に抽出して再実行し、結果を比較します。

**注**
- [41] サブプロセス：実行中の別のプログラムが起動するプログラムです。
- [42] C 拡張：Python から呼び出される C で書かれた部品で、高速ですが、それが読むファイルを Python は把握できません。
- [43] 監査フック：Python に組み込まれた「ファイルが開かれたら知らせる」仕組みで、aib はこれを使ってテストが読んだものを記録します。
- [44] C コンパイラ：C のソースコードを実行可能なプログラムに変換するツールです（たとえば `cc`、`gcc`、`clang`）。

## プライバシー

aib があなたのコード、テスト結果、その他のデータを私たちに送ることはありません。記録はあなたのマシンに残ります
（`~/.ez2-aib/` と、`~/.cache/ez2-aib/` の小さなキャッシュ）。aib 自身のネットワーク通信は、`aib ship` が git で行うもの、
つまり**あなた自身の**リモート<sup>[45]</sup>との fetch と push だけです。

コックピットには 1 つだけ違いがあります：あなたが開く AI の席は AI ベンダー自身のツールであり、それらはいつもどおり各ベンダーと通信します。
コックピット自体があなたのマシンに保存するものは、すべて `~/.ez2-aib/` の下にあります：
席の記録と引き継ぎメモ、席どうしのメッセージ、プロジェクトカードと役割カード、そして API キーの席のために追加した API キー
（`~/.ez2-aib/secrets/` 内、フォルダは 0700／ファイルは 0600<sup>[46]</sup>、隣に保存されたキーで暗号化。これは何気なく見られることや
誤ったコミットを防ぐためのもので、すでにあなたのホームフォルダを読める人を防ぐものではありません）。`~/.ez2-aib/` を削除すると、これらはすべて消えます。

**注**
- [45] リモート（fetch／push）：オンラインに置かれたコードのコピー（たとえば GitHub 上）で、fetch はそこからダウンロードし、push はそこへアップロードします。
- [46] 0700／0600：自分のアカウントだけが読み書きできることを意味するファイル権限です。

## ネイティブ安全網（Linux のみ）

一部のテストは C コード（ネイティブ拡張、C ライブラリ）からファイルを読みますが、これは Python の監査フックからは見えません。
Linux では、PATH 上に C コンパイラ（`cc`、`gcc`、`clang` のいずれか）があれば、aib は同梱の小さな C ファイル
（`aib/tools/verify/ldp-shim/`）を `~/.cache/ez2-aib/` にコンパイルし、それを**テストプロセスにだけ**プリロード（`LD_PRELOAD`<sup>[47]</sup>）して、
そうした読み込みも記録します。コンパイラがない場合やライブラリを読み込めない場合、安全網はオフのままとなり、aib がその理由を表示します。
**その場合、上で説明した抜け穴が開いたままになります：** C コードで行われた読み込みは記録されないため、そうしたファイルを変更しても
テストが再実行されないことがあります。macOS では利用できません。
`AIB_NATIVE_GUARD=0` でオフにできます。

**注**
- [47] `LD_PRELOAD`：プログラムの起動時に小さな部品を読み込ませる Linux の機能で、aib は C で行われた読み込みを記録するために使います。

## 一時フォルダをきれいに保つ

テストはしばしば一時ファイルを残し、ときにはバックグラウンドプログラムも残します（テストが止め忘れた tmux サーバーが何時間も動き続け、
何ギガバイトものメモリを消費することもあります）。aib は自分が実行したテストの後片付けをします：

- 各テストには専用の一時フォルダ（`TMPDIR`<sup>[48]</sup>、`<tmp>/aibt-…` の下）が与えられ、テストの終了時に削除されます。
- テストが起動して動かしたままにしたバックグラウンドプログラムは、テストの終了時に停止されます。
- サマリーには何かを残したテストの名前が表示されるので、原因から修正できます。
- `aib tmp` は、aib とそのテストが一時フォルダに残したものと、すでに終了したテストが残したバックグラウンドプログラムを一覧表示します。
  `aib tmp --apply` でそれらを削除します。aib のものではないもの、シンボリックリンク、実行中のプログラムがまだ使っているものには決して触れません。
  `aib ship` はプッシュ前チェックの前にこれを自動で行います。

**注**
- [48] `TMPDIR`：一時ファイルをどこに置くかをプログラムに伝える設定です。

## CI

`aib ship ci` は、aib の記録を Actions のキャッシュに保持する GitHub Actions<sup>[49]</sup> のワークフロー<sup>[50]</sup>を書き出すため、CI<sup>[51]</sup> でも
変更があった部分だけが実行されます。フォーク<sup>[53]</sup>からのプルリクエスト<sup>[52]</sup>は常にすべて実行されます（それらが記録に触れられないようにするためです）。

**注**
- [49] GitHub Actions：GitHub の自動化サービスで、コードをプッシュするとテストを自動で実行します。
- [50] ワークフロー：GitHub Actions の設定ファイルで、実行する手順を並べたものです。
- [51] CI（継続的インテグレーション）：誰かがコードをプッシュするたびに、クラウドでテストを自動実行することです。
- [52] プルリクエスト（PR）：プロジェクトの所有者に自分の変更を取り込んでもらうよう依頼するものです。
- [53] フォーク：誰かが自分のアカウントの下に作った、あなたのプロジェクトのコピーです。

## トラブルシューティング

| 表示されたもの | 意味・対処 |
|---|---|
| `aib:「…」というコマンドはありません` | 打ち間違いか、このバージョンにないコマンドです。`aib --help` で一覧できます。 |
| `…この aib にはこの機能が含まれていません` | 完全版のコマンドです(ホストをまたぐフリート、協作広場、レポートなど)。オープンソース版はそれなしで使えます。 |
| `aib newrole` や第二の脳が `EZ2_ROUTE_REGISTRY` を求める | 自分のナレッジベース(`EZ2_VAULT_DIR`、または `~/Desktop/Obsidian/Ez2`)があるので、aib はフォルダーを推測しません。`EZ2_ROUTE_REGISTRY` を自分のルート契約に向けるか、`EZ2_VAULT_DIR` を外して aib 自身の `~/.ez2-aib/vault` を使ってください。 |
| インストーラーが `~/.local/bin` に別の `aib` があると言う | 既存の aib はそのまま使えます。オープンソース版は `~/ez2-aib` に並べて置かれます。コックピットを試すには別の macOS ユーザーアカウントを使ってください。 |
| その他 | `aib support` が個人情報を除いたレポートをまとめます(何も送信しません)。GitHub の issue に添付してください。 |

## アンインストール

```sh
aib uninstall                            # 削除される内容を一覧表示（何も変更しません）
aib uninstall --yes                      # この aib（ワンライナーでインストールしたもの）を削除。同じコンピューター上の別の aib には触れません
aib uninstall --all --yes                # aib の記録とキャッシュも削除（~/.ez2-aib は先に ~/ez2-aib-backup-<時刻>.tar.gz へバックアップ）
pipx uninstall ez2-aib                   # pipx でインストールした場合
rm -rf your-project/.aib                 # `aib ship` が作成したもので、もう不要な場合のみ
```

## ローカルファーストである理由

開発のすべてがリモートのホストやオンラインプラットフォームに依存していると、それが停止したり接続できなくなったりした瞬間に、すべてが止まってしまいます。
aib はまさにその経験から生まれました：私たちは開発をオンラインプラットフォームから自分たちのコンピューターに戻し、記録、記憶、
進行中の作業がローカルマシンに残り、リモートで何かが故障しても作業を続けられるようにしました。

AI 自体は引き続き各ベンダーのサービスに接続しますが、席の記録、人格、記憶はあなたのコンピューターにあります。
別のベンダーの AI に切り替えても、ネットワークの復旧を待っても、中断したところからそのまま再開できます。

## 沿革

AIB は、私たちが 2024 年に開発を始めた **ACB** の後継です。
ACB のアーキテクチャは現在の使われ方に合わなくなったため、これ以上手を加えるのではなく、AIB として一から作り直しました。
`aib test` と `aib ship` は、その作り直しにおけるオープンソースの中核部分です。
