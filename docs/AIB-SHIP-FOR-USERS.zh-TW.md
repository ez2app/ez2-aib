# aib 幫你推版省多少時間:給用戶的說明

一句話:**每次推新版之前,aib 只重跑這次改動真的會影響到的測試,其他照上次的結果沿用;每次都告訴你這次省了多少、從開始用到現在一共省了多少。**

(指令細節在 `docs/AIB-TEST-QUICKSTART.zh-TW.md` 第 6 節;這份只講你會看到什麼、怎麼讀、怎麼省最多。)

---

## 1. 第一次開始用(大約 5 分鐘,加上全部測試跑一次的時間)

```bash
cd ~/你的專案
aib ship init
```

它會依序做這些事,**不推、不提交**:
1. 列出專案名稱、找到版號放在哪、找到你的測試。
2. 確認測的是**這個資料夾裡的程式**(不是別處裝好的同名套件);不是就直接告訴你,不會假裝通過。
3. 把全部測試跑一次,記下每支測試讀了哪些檔。這次不會省時間,是在建紀錄。
4. 告訴你之後每次大概能省多少、哪幾個檔一改就牽動最多測試。

## 2. 每次推之前,你會看到這樣的預告

以下是 aib 自己這個專案 10-07 早上一次真實的推送(**範例,你的專案數字會不同**):

```
這次推前檢查:929 支測試
├─ 沒有 aib(一支一支跑):約 3.2 小時
├─ 有 aib(這台):預計約 10 分鐘 —— 從 07:01 開始,預計 07:11 完成
└─ 加開機器一起跑(規劃中,推算):2 台約 8.3 分鐘、4 台約 8.3 分鐘
```

怎麼讀:
- **沒有 aib**:你的全部測試一支接一支跑完要多久(用每支上次真的跑的秒數加起來)。
- **有 aib**:這次只跑受影響的、而且分幾份同時跑,預計多久、幾點完成。
- **加開機器**:如果有別台閒置機器一起分工,推算可以再快多少(「最慢那一支」是下限,所以台數加到某個程度就不會再快)。

## 3. 跑完之後的對帳

```
這次推前檢查結果
├─ 沒有 aib 要等:約 3.2 小時
├─ 有 aib 實際花:11.4 分鐘(少等 3 小時,約 94%)
│  └─ 影子續跑再省:約 52.7 分鐘(沿用 44 支)
└─ 從第一次到現在:推 6 次,沒有 aib 要 19.6 小時,實際 4.9 小時,共少等 14.7 小時
```

- 「少等」分兩塊:**同時跑**(幾份一起跑)省下的,和**影子續跑**(沒受影響的測試直接沿用上次結果)再省的。
- 「從第一次到現在」是從你第一次用開始的總帳,每一次都照實加上去,不是估的。
- 想看每一次、每一週的明細:`aib ship stats`。

## 4. 什麼情況下省最多(你可以怎麼做)

| 你這次改了什麼 | 會發生什麼 | 你可以怎麼做 |
|---|---|---|
| 一般程式碼 | 只重跑讀到它的測試,最省 | 照常推 |
| 很多測試都會讀的檔(共用設定、共用工具) | 讀它的測試全部重跑 | 這類檔的改動**攢在一起推**,其他次推送就能大量沿用;`aib ship hotfiles` 列出是哪幾個 |
| 翻譯字典(每句一個鍵的那種) | 只重跑**用到那幾句**的測試 | 照常推;要是某支測試整份字典拿去比對或複製,那支照樣重跑(對的) |
| 套件鎖檔(requirements、lock 檔) | 全部重跑 | 升套件時一次升完,不要分好幾次 |

`aib ship stats` 的最後幾行會用**你自己的推送紀錄**告訴你:只改一般程式碼的推送平均每次沿用幾支、占全部測試時間幾 %,
以及你的推送裡有多少次落在「全部重跑」的那幾種。

## 5. 一定要知道的三件事

1. **紅燈永遠不會被沿用成綠燈。** 只有「上次是綠、而且它讀的每個檔都沒變」才沿用;讀了什麼量不到的測試,每次都實跑。
2. **「沒驗」不等於綠。** 這台缺某個工具(例如 Mac 才有的指令)、或量不到的測試,會照實列成「沒驗」,不會算成通過。
3. **想確認沿用對不對**:`aib ship audit` 會抽幾支「沿用」的測試真的重跑,比對結果,記進總帳。

## 6. 目前還不支援

- Windows。
- Python 以外的語言:能用到什麼程度看上面的語言表(10-07 實測過 Node、jest/mocha、Go、PHP;vitest 跑得對但每次重跑;Ruby、Rust、Java 等要自己宣告指令,每次實跑)。
- 只看時鐘、不讀任何檔的時間相依測試(例如「超過 30 天算過期」),靠紀錄期限兜底,最晚 14 天後才會重跑。
