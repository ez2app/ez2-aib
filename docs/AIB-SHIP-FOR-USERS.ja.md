# プッシュ時に aib でどれだけ時間を節約できるか：ユーザー向けガイド

一言でいうと、**aib はプッシュのたびに、今回の変更が実際に影響しうるテストだけを再実行し、それ以外は前回の結果を再利用します。毎回、今回のプッシュでどれだけ節約できたか、使い始めてから累計でどれだけ節約できたかを表示します。**

（コマンドの詳細は `AIB-TEST-QUICKSTART.ja.md` の 6 章にあります。このガイドでは、何が表示されるか、どう読むか、どうすれば最も節約できるかだけを扱います。）

---

## 1. はじめに（約 5 分 ＋ すべてのテストを 1 回実行する時間）

```bash
cd ~/your-project
aib ship init
```

次の処理を順に行います。**プッシュもコミットもしません**：
1. プロジェクト名を表示し、バージョンの保存場所を探し、テストを探します。
2. テストが**このフォルダ内のコード**（別の場所にインストールされた同名パッケージではなく）をテストしていることを確認します。そうでなければ、合格を装わずにすぐに知らせます。
3. すべてのテストを 1 回実行し、各テストが読んだファイルを記録します。この実行では時間は節約されません。記録を作るための実行です。
4. 今後毎回どのくらい節約できるかの目安と、変更すると最も多くのテストに影響するファイルを示します。

## 2. プッシュのたびに、次のようなプレビューが表示されます

以下は aib プロジェクト自身の実際のプッシュです（**例です。お使いのプロジェクトの数値は異なります**）：

```
This pre-push check: 929 tests
├─ without aib (one test after another): about 3.2 h
├─ with aib (this machine): about 10 min — started 07:01, expected to finish 07:11
└─ more machines together (planned, projected): 2 machines about 8.3 min, 4 machines about 8.3 min
```

読み方：
- **aib なし**：すべてのテストを 1 件ずつ順に実行した場合の所要時間（各テストの直近の実際の実行時間の合計）。
- **aib あり**：今回は影響を受けるテストだけを実行し、シャードに分けて並列に実行します。その見込み所要時間と終了予定時刻です。
- **マシンを増やした場合**：空いているマシンで作業を分担した場合にどれだけ速くなるかの予測です（最も遅い単一のテストが下限になるため、ある台数を超えるとそれ以上速くなりません）。

## 3. 実行後の精算

```
This pre-push check, in the end
├─ without aib you would wait: about 3.2 h
├─ with aib it actually took: 11.4 min (3 h less waiting, about 94%)
│  └─ extra savings from shadow resume: about 52.7 min (44 tests reused)
└─ since the first run: 6 pushes; without aib 19.6 h, actual 4.9 h, 14.7 h less waiting in total
```

- 「待ち時間の短縮」は 2 つの部分からなります。**並列実行**（複数のシャードを同時に実行）による節約と、その上に加わる**シャドウレジューム**（影響を受けないテストが前回の結果を再利用）による節約です。
- 「初回実行以降」は aib を初めて使ってからの累計です。毎回の実行は推定ではなく、実際の値で加算されます。
- 実行ごと・週ごとの詳細：`aib ship stats`。

## 4. 最も節約できるとき（とできること）

| 変更したもの | どうなるか | できること |
|---|---|---|
| 通常のコード | それを読むテストだけが再実行されます。節約効果が最も大きいケースです | いつもどおりプッシュ |
| 多くのテストが読むファイル（共通の設定、共通のユーティリティ） | それを読むすべてのテストが再実行されます | **これらのファイルへの変更を 1 回のプッシュにまとめる**と、ほかのプッシュで大幅に再利用できます。どのファイルが該当するかは `aib ship hotfiles` で一覧表示できます |
| 翻訳辞書（文字列ごとに 1 キー） | **その文字列を使う**テストだけが再実行されます | いつもどおりプッシュ。テストが辞書全体を比較またはコピーしている場合、そのテストは引き続き再実行されます（それが正しい動作です） |
| パッケージのロックファイル（requirements、lock ファイル） | すべて再実行されます | パッケージは何回にも分けず、一度にまとめてアップグレード |

`aib ship stats` の最後の数行では、**あなた自身のプッシュ履歴**をもとに、通常のコードだけを変更したプッシュで平均何件のテストが再利用され、それがテスト時間全体の何パーセントにあたるか、
そしてプッシュのうち何回が「すべて再実行」のケースに該当したかを示します。

## 5. 必ず知っておくべき 3 つのこと

1. **赤の結果が緑として再利用されることはありません。** 結果が再利用されるのは「前回が緑で、読んだファイルがどれも変わっていない」場合だけです。計測できないものを読むテストは毎回実際に実行されます。
2. **「未検証」は緑ではありません。** このマシンにツールがないテスト（例：Mac 専用のコマンド）や計測できないテストは、正直に「未検証」として表示され、合格として数えられることはありません。
3. **再利用が正しいか確認するには**：`aib ship audit` が「再利用された」テストの一部を実際に再実行して結果を比較し、累計に記録します。

## 6. 未対応

- Windows。
- Python 以外の言語：どこまで対応しているかは `AIB-TEST-QUICKSTART.ja.md` の言語表を参照してください（Node、jest/mocha、Go、PHP で確認済み。vitest は正しく実行されますが毎回再実行されます。Ruby、Rust、Java などはコマンドを自分で宣言する必要があり、毎回実際に実行されます）。
- 時計だけを見てファイルを読まない時間依存のテスト（例：「30 日より古ければ期限切れ」）は記録の有効期限でしかカバーされないため、最大 14 日後まで再実行されないことがあります。
