# aib

### AI Basic to AI Best

**所有最好的 AI,都來自一個好的基礎。**

aib(AI Basic)的名字就是它的初衷:當 AI 最好的基礎。各家 AI 都在變強,但要把它們真正用起來,還缺一個共同的地基:
讓不同的 AI 能並肩工作、有自己的人格和記憶、換手不斷線、改動有安全網。aib 就是這個地基,你在上面打造屬於你的最好的 AI。

我們要做的,是**最容易使用、最人性化的 AI 工具基礎**:不用懂架構,一行就裝好;用你習慣的方式和 AI 說話,其他的交給 aib。
我們也要讓帶領一群 AI 像玩遊戲一樣:每個 AI 都是一位看得見的虛擬小夥伴,看得出它在忙什麼、累不累,點一下就能交辦
(虛擬小夥伴會先做在 Claude Code 的 mod 裡,還在開發中,尚未對外開放)。

**多個 AI 共存協作:免費接入各家 AI,每一席都有自己的人格、專業和記憶,換哪個 AI 都能接續工作,突然斷線也不會遺失。**

- **免費接入各家 AI**:aib 本身免費、開源<sup>[1]</sup>。寫程式的 AI 工具<sup>[2]</sup>、
  用 API 金鑰<sup>[3]</sup> 接的模型<sup>[4]</sup>、桌面 AI App(Claude、Codex Desktop…)都能開成席位<sup>[5]</sup> 一起工作。
  各家 AI 用你自己的帳號或金鑰,aib 不另外收費。
- **每個 aib 有自己的艙<sup>[6]</sup>,每一艙有自己的席位**:一艙就是一個 tmux<sup>[7]</sup> 視窗,裡面並排多個 AI 席位,
  每席有自己的角色(`dev`、`qa`、`pm`…),席位之間可以互傳訊息、互相派工。
- **每個 AI 都有自己的人格和專業**:每一席可以有自己的人格<sup>[8]</sup>(第一大腦:個性、說話方式、做事原則),
  也可以有自己的專業(開發、測試、企劃…)。
- **不只一種答案,多品牌 AI 互相挑錯**:同一個問題交給不同品牌的 AI,各自回答、再互相檢查,
  找出彼此的弱點和盲點,不會只聽單一家 AI 的說法。
- **隨時記進第二大腦**<sup>[9]</sup>:開發或討論到一半,隨時把重點和決定記進第二大腦(專案記憶)。
  不怕斷線、當機;AI 聊太久開始變笨時,直接重開一席,記憶照樣接上。
- **隨時換 AI 接手**:同一席今天用 Claude、明天換 Codex,人格和專案記憶照樣接上;對話快滿時會留交接筆記給下一棒。
- **保存珍貴對話、減少 AI 幻覺**<sup>[10]</sup>:對話中值得留下的重點,會被萃煉<sup>[11]</sup>成人格和記憶的候選,經你核准後寫進去。
  AI 有寫下來的事實可以查,比較不會憑印象亂猜。
- **全部存在你的電腦**:席位紀錄、交接筆記、人格和專案記憶全都存在你自己的電腦(`~/.ez2-aib/`<sup>[12]</sup>),不上傳。

駕駛艙在 macOS 上搭配 tmux 執行。多個 AI 改同一份程式碼,改動就多,所以 aib 也內建一套安全網,
不開 AI 席位也能單獨用(Linux、macOS 皆可):

- `aib test` 只重跑這次改動影響到的測試<sup>[13]</sup>(Python、bash、Node<sup>[14]</sup> 都追得到),其他的沿用上次的**綠燈**<sup>[15]</sup>。
  紅燈永遠不沿用;aib 量不到的,一律照跑。
- `aib ship` 是推前檢查<sup>[16]</sup>:只有沒有新紅燈的那一包才會推上去。發版只能由人在終端機<sup>[17]</sup> 上做。

**註**
- [1] 開源:程式碼公開,任何人都能看、能用、能改。
- [2] 寫程式的 AI 工具:Claude Code(Anthropic)、Codex(OpenAI)、Antigravity(Google)、GitHub Copilot(GitHub)、Grok(xAI)等,各家出的 AI 寫程式助手。
- [3] API 金鑰:AI 服務發給你的一串密碼,程式拿它代表你去呼叫那家的 AI。
- [4] 用 API 金鑰接的模型:例如 DeepSeek、OpenRouter(一個入口接很多家模型)、NVIDIA。
- [5] 席位:駕駛艙裡的一個 AI 工作位置,一席一個 AI,有自己的角色與記憶。
- [6] 艙(駕駛艙):aib 開的一個工作畫面,裡面並排好幾個席位。
- [7] tmux:讓一個終端機視窗切成好幾格、關掉視窗也能繼續跑的工具。
- [8] 人格:這一席的個性、說話方式、做事原則,存成一張人格卡,換哪家 AI 開這一席都會載入。
- [9] 第二大腦:這一席的專案記憶,是存在你電腦裡的一份份筆記。
- [10] AI 幻覺:AI 一本正經地講出不正確的內容。
- [11] 萃煉:從對話裡挑出值得留下的重點,整理成一條條規則或知識。
- [12] `~/.ez2-aib/`:你電腦裡家目錄底下的一個資料夾,aib 的紀錄都放這裡。
- [13] 測試:用來自動檢查程式有沒有寫壞的小程式。
- [14] Python、bash、Node:三種常見的程式語言 / 執行環境。
- [15] 綠燈 / 紅燈:測試通過叫綠燈,沒通過叫紅燈。
- [16] 推前檢查:把程式推上共用版本(主線)之前,先跑一次受影響的測試。
- [17] 終端機:輸入文字指令的視窗(macOS 的「終端機」App)。

## 快速開始

```sh
curl -fsSL https://raw.githubusercontent.com/ez2app/ez2-aib/main/install.sh | bash
# 把最新正式版裝到 ~/ez2-aib;之後隨時再跑同一行就是更新(Linux 只裝測試安全網;駕駛艙需要 macOS)
aib update                                          # 裝好之後也可以這樣更新(aib update --tools 會再問要加裝哪些 AI 工具)
# 其他裝法:pipx install ez2-aib    (還沒有 pipx?macOS:brew install pipx / Linux:python3 -m pip install --user pipx,
#                                    再跑 pipx ensurepath、開一個新的終端機)
#          git clone https://github.com/ez2app/ez2-aib ~/ez2-aib && export PATH="$HOME/ez2-aib/bin:$PATH"

cd your-project
aib claude safe dev                  # 開一個叫 dev 的 Claude Code 席位(每個動作都先問你)
aib codex safe qa                    # 旁邊再開一個叫 qa 的 Codex 席位
aib test tests/test_something.py     # 第一次:實跑並記下來
aib test tests/test_something.py     # 什麼都沒改:沿用
aib test --all                       # 整套測試,同樣的規則
aib ship package --branch my-branch  # 推前檢查,過了就推上主線
```

Python<sup>[18]</sup> 3.9 以上,Linux 或 macOS;駕駛艙需要 macOS 和 tmux。不支援 Windows(WSL2<sup>[19]</sup> 沒有測過)。
第一行是一行安裝<sup>[20]</sup>;其他裝法用到 pipx<sup>[21]</sup>、git<sup>[22]</sup>、PATH<sup>[23]</sup>。

**註**
- [18] Python:一種程式語言;aib 本身用它寫成,電腦上要先裝好。
- [19] WSL2:在 Windows 裡跑 Linux 的功能。
- [20] 一行安裝:`curl … | bash` 把安裝程式下載下來並直接執行。
- [21] pipx:安裝 Python 指令工具的工具,每個工具各自隔開、不互相干擾。
- [22] git:記錄程式碼每次改動的版本管理工具;`git clone` 是把整份程式碼抓下來。
- [23] PATH:電腦找指令的資料夾清單;把資料夾加進去,打 `aib` 才找得到。

## 駕駛艙:多個 AI 並排

**駕駛艙**把幾個 AI 寫程式助手(「席位」)並排開在同一個 tmux 視窗,每席有自己的角色(`dev`、`qa`、`pm`…),
左中右三欄、滑鼠選單、席位互傳訊息、對話快滿時的交接筆記,以及艦隊工具<sup>[24]</sup>(席位身分、派工、巡查)。

```sh
aib claude safe dev        # 開一席 Claude Code,角色 dev,每個動作先問你
aib codex dgrs qa          # 開一席 Codex,角色 qa,全部放行(見下)
aib --help-cockpit         # 所有選項
```

- **需要:**macOS 和 tmux。每家 AI 自己的命令列工具<sup>[25]</sup> 要先裝好、登入好(`claude`、`codex`、`grok`…),aib 不幫你裝也不幫你登入。
  駕駛艙還沒在 Linux 上試過。
- **macOS 上的 bash 測試:** aib 追蹤 bash 腳本要 bash 4.1 以上。macOS 內建的是 3.2,跑 bash 腳本的測試會判「量不到」、每次重跑
  (安全,只是比較慢)。`brew install bash`<sup>[26]</sup> 之後就能沿用。
- **權限模式,每席自己選:**`safe` 保留 AI 工具原本的保護(改檔、跑指令前會問你);`dgrs` **只對那一席**關掉這些保護,
  AI 不問就做,開席時 aib 會印警告和改用 `safe` 重開的指令。開每一席時自己決定。
- **Claude** 是 Anthropic 的商標;Codex 是 OpenAI 的;Grok 是 xAI 的。aib 與它們沒有關係。

**註**
- [24] 艦隊工具:同時管很多席位用的功能,例如查每一席是誰、分派工作、定時巡查。
- [25] 命令列工具:在終端機裡打指令使用的程式(例如 `claude`、`codex`)。
- [26] `brew install bash`:用 Homebrew(macOS 上裝軟體的工具)裝新版的 bash。

- [28] 主機:一台跑程式的電腦,可以是你的筆電、公司的電腦,或租用的雲端機器。

## 開發中的功能:測試加速

> 這一部分還在開發,下面的數字與行為之後可能會變。

aib 記住每支測試讀過哪些檔,下次只重跑受改動影響的,其他沿用上次的綠燈。

**實測:我們自己開發 aib 的紀錄**(2026-10-08~10-10,推送<sup>[29]</sup> 28 次,每次約 1,020 支測試)

| 跑法 | 28 次推送共花 | 平均每次 | 比「一支一支跑」省下 |
|---|---|---|---|
| 不用 aib,一支一支跑<sup>[30]</sup> | 91.1 小時(約 3.8 天<sup>[31]</sup>) | 195 分鐘 | (基準)91.1 小時 |
| 用 aib,同專案單份跑<sup>[32]</sup> | 43.8 小時(約 1.8 天) | 94 分鐘 | 省 47.3 小時(約 2 天,52%) |
| **用 aib,同專案拆成 3 份跑** | **16.6 小時(約 0.7 天)** | **36 分鐘** | **省 74.5 小時(約 3.1 天)** |

- 從 91.1 小時到 43.8 小時,是 aib 沿用<sup>[33]</sup> 省的:沒受影響的測試不用再跑;再到 16.6 小時,是把剩下要跑的拆成 3 份同時跑。
- 平均每次 36 分鐘是這 28 次的平均;紀錄累積後,最近 10 次平均約 18 分鐘,越用越快。
- 沿用有沒有出錯:隨機抽 13 支沿用的測試真的重跑,13 支結果都一致,0 支沿用錯。

**一個月預期可省**<sup>[34]</sup>

| 跑法 | 一個月約花 | 比「一支一支跑」省下 |
|---|---|---|
| 不用 aib,一支一支跑 | 395 小時(約 16.4 天) | (基準)395 小時 |
| 用 aib,同專案單份跑 | 190 小時(約 7.9 天) | 省 205 小時(約 8.5 天) |
| **用 aib,同專案拆成 3 份跑** | **72 小時(約 3 天)** | **省 323 小時(約 13.5 天)** |

**小專案(Linux、4 核心)**

| 專案 | pytest<sup>[35]</sup> 平行跑 | aib 第一次跑 | 之後每次可省 |
|---|---|---|---|
| [attrs](https://github.com/python-attrs/attrs)<sup>[36]</sup>(26 支) | 8.2 秒 | 15.1 秒 | 約 5 秒(沒改檔時 3.0 秒跑完) |
| [click](https://github.com/pallets/click)<sup>[37]</sup>(43 支) | 6.2 秒 | 17.2 秒 | 約 2 秒(沒改檔時 3.8 秒跑完) |

- 第一次要把每支測試讀過哪些檔都記下來,所以比 pytest 慢;從第二次起,沒受影響的測試直接沿用。
- 「之後每次可省」是沒改檔時的情況;改到越多檔,要重跑的越多,省得越少。
- **適合:**全套要跑幾分鐘以上,每次只改一部分。**不適合:**全套幾秒就跑完。
- 附帶好處:每支測試單獨跑,能抓出「要靠別支先跑才會過」的測試。

**註**
- [29] 推送:把改好的程式送上大家共用的版本。
- [30] 一支一支跑:91.1 小時是把每支測試在 aib 底下量到的秒數加總的估算,含追蹤的額外時間,所以偏高。
- [31] 天:以 1 天 24 小時計算(AI 可以整天不停地跑)。
- [32] 同專案單份跑:aib 只跑受影響的測試、一支接一支跑;43.8 小時是那些測試實跑秒數的加總。
- [33] 沿用:測試讀過的檔都沒變,就直接用上次的綠燈結果,不再重跑。
- [34] 一個月預期可省:照實測期間的頻率(每週約 28 次,一個月約 121 次)× 52 ÷ 12 推算;推送次數越少,省得越少。每推一次,比一支一支跑約省 160 分鐘,其中 aib 沿用省約 101 分鐘。
- [35] pytest:Python 最常用的測試工具,一次跑完所有測試、告訴你哪些過了;「平行跑」是同時開好幾個行程,是它最快的跑法。
- [36] attrs:知名的開源 Python 套件,幫寫程式的人少寫重複的程式碼。
- [37] click:知名的開源 Python 套件,用來做打指令的工具。

## 支援的語言

Python(unittest<sup>[38]</sup>、pytest)完整追蹤。Node(node:test、jest、mocha<sup>[39]</sup>)、Go、PHP<sup>[40]</sup> 可以經 aib 跑,也有推前檢查;
能沿用多少要看追蹤器看得到多少 —— 目前的對照表見 `docs/AIB-TEST-QUICKSTART.zh-TW.md`。
其他語言可以在 `.aib/ship.toml` 宣告測試指令;它們每次都會照跑,但打包和發版照常可用。

**註**
- [38] unittest:Python 內建的測試工具。
- [39] node:test、jest、mocha:Node 常用的三種測試工具。
- [40] Go、PHP:另外兩種程式語言。

## 沿用有多安全?

- 只沿用綠燈,而且只有在測試讀過的每一個輸入都一個位元組都沒變的時候。
- aib 看不到測試讀了什麼(追不到的子行程<sup>[41]</sup>、網路、已知會自己讀檔的 C 擴充<sup>[42]</sup>)⇒ 那支標成「量不到」,每次都照跑。
- **已知的缺口:**不在 aib 名單上、又在 C 層自己讀檔的 C 擴充,Python 的稽核鉤子<sup>[43]</sup> 看不到。Linux 上由下面的原生安全網補;
  **沒有安全網時(macOS,或沒有 C 編譯器<sup>[44]</sup>),這種檔改了,測試可能不會重跑。**你的測試若依賴這樣讀的檔,
  發版前跑一次 `aib test --fresh`。
- `aib ship audit` 會隨機抽幾支「沿用」的測試真的重跑、比對結果。

**註**
- [41] 子行程:程式在執行中另外開出來的程式。
- [42] C 擴充:用 C 語言寫、給 Python 呼叫的元件,跑得快,但它讀檔 Python 看不到。
- [43] 稽核鉤子:Python 內建的「開檔時通知我」機制,aib 靠它記下測試讀了哪些檔。
- [44] C 編譯器:把 C 語言原始碼變成可執行程式的工具(例如 `cc`、`gcc`、`clang`)。

## 隱私

aib 不會把你的程式碼、測試結果或任何資料傳給我們。紀錄只存在你自己的電腦上(`~/.ez2-aib/`,外加 `~/.cache/ez2-aib/`
一小份快取)。aib 自己的網路流量,只有 `aib ship` 用 git 對**你自己的**遠端<sup>[45]</sup> 做 fetch 與 push。

駕駛艙有一點不同:你開的 AI 席位就是各家 AI 自己的工具,它們照常連自家的服務。駕駛艙自己存在你電腦上的,全在 `~/.ez2-aib/` 底下:
席位紀錄與交接筆記、席位互傳的訊息、專案卡與角色卡,以及你為 API 金鑰席位加的金鑰(在 `~/.ez2-aib/secrets/`,資料夾 0700、
檔案 0600<sup>[46]</sup>,用放在旁邊的金鑰加密 —— 防的是隨手看到和不小心提交,擋不住已經能讀你家目錄的人)。刪掉 `~/.ez2-aib/` 就全部清掉。

aib 會改到自己資料夾以外的東西:開席時,它會在那家 AI 工具的設定裡加幾個掛點(hook),讓駕駛艙跟得上那一席 ——
`~/.claude/settings.json`(對話開頭的狀態提醒、席位信箱、權限選單自動判斷、依用量自動整理記憶)、`~/.codex/hooks.json`、
`~/.grok/hooks/aib-*.json`、`~/.copilot/hooks/aib-*.json` 和 `~/.gemini/config/hooks.json`。你自己的設定不會被動到,
每次改之前會先複製一份 `<檔名>.bak-…`。狀態提醒只會提醒;只有你寫進 `~/.ez2-aib/state/seat-now/gate-seats.txt` 的席位
(或 `*`)才會在回合結束時被擋下。`aib init` 也會在桌面放一個通往你筆記的捷徑。`aib uninstall` 會把這些全部拿掉。

**註**
- [45] 遠端(fetch / push):放在網路上的那份程式碼(例如 GitHub);fetch 是抓下來,push 是推上去。
- [46] 0700 / 0600:檔案權限,表示只有你自己的帳號能讀寫。

## 原生安全網(只在 Linux)

有些測試是由 C 程式(C 擴充、C 函式庫)讀檔的,Python 的稽核鉤子看不到。
在 Linux 上,如果 PATH 上有 C 編譯器(`cc`、`gcc` 或 `clang`),aib 會把它自帶的一小段 C 原始碼
(`aib/tools/verify/ldp-shim/`)編譯到 `~/.cache/ez2-aib/`,並用 `LD_PRELOAD`<sup>[47]</sup> **只掛進測試行程**,讓這類讀檔也記得到。
沒有編譯器、或程式庫掛不上 ⇒ 安全網不開,aib 會說明原因。**這時上面那個缺口是開著的:**C 層讀的檔記不到,
那種檔改了,測試可能不會重跑。macOS 上一律沒有這層。
要關掉:`AIB_NATIVE_GUARD=0`。

**註**
- [47] `LD_PRELOAD`:Linux 的功能,讓一個程式啟動時先載入指定的小元件;aib 用它記下 C 層的讀檔。

## 暫存區保持乾淨

測試常會留下暫存檔,有時還會留下背景程式:一個忘了關的 tmux 伺服器可以跑上好幾個小時、吃掉好幾 GB 記憶體。aib 會替它跑的測試收尾:

- 每支測試有自己的暫存資料夾(`TMPDIR`<sup>[48]</sup>,在 `<tmp>/aibt-…` 底下),測試結束就刪。
- 測試開了沒關的背景程式,測試結束時一併結束。
- 總表會點名哪幾支測試留了東西,方便你從源頭修。
- `aib tmp` 列出 aib 和它的測試留在暫存區的東西,以及已經結束的測試留下、還在跑的背景程式;`aib tmp --apply` 才真的清。
  不是 aib 的東西、捷徑、還有程式在用的,一律不碰。`aib ship` 推前會自動做一次。

**註**
- [48] `TMPDIR`:告訴程式「暫存檔放哪裡」的設定。

## CI

`aib ship ci` 會寫一份 GitHub Actions<sup>[49]</sup> workflow<sup>[50]</sup>,把 aib 的紀錄存在 Actions 快取裡,所以 CI<sup>[51]</sup> 也只跑有變的。
從 fork<sup>[52]</sup> 來的 PR<sup>[53]</sup> 一律全部照跑(它們不准碰到紀錄)。

**註**
- [49] GitHub Actions:GitHub 提供的自動化服務,推程式上去就自動跑測試。
- [50] workflow:寫給 GitHub Actions 的設定檔,說明要自動做哪些步驟。
- [51] CI(持續整合):每次有人推程式,就自動在雲端跑一次測試。
- [52] fork:別人把你的專案複製一份到他自己的帳號下。
- [53] PR(Pull Request):請專案主人把自己的改動合進去的申請。

## 常見問題

| 你看到 | 意思/怎麼辦 |
|---|---|
| `aib:沒有「…」這個指令` | 打錯字,或這一版沒有這個指令。`aib --help` 列出全部。 |
| `…這個功能還在開發中` | 這個指令(跨主機艦隊、協作廣場、報告等)還在開發中、尚未對外開放;其他功能不用它也能正常用。 |
| `aib newrole`/第二大腦要你設 `EZ2_ROUTE_REGISTRY` | 你設了自己的知識庫(`EZ2_VAULT_DIR`,或電腦上有 `~/Desktop/Obsidian/Ez2`),aib 不會替你猜資料夾。把 `EZ2_ROUTE_REGISTRY` 指到你的路由契約;或拿掉 `EZ2_VAULT_DIR`,改用 aib 自己的 `~/.ez2-aib/vault`。 |
| 安裝時說 `~/.local/bin` 已經有別的 `aib` | 你原本的 aib 照常可用,開源版放在旁邊的 `~/ez2-aib`。要用它試駕駛艙,請另開一個 macOS 使用者帳號。 |
| 其他 | `aib support` 會打包一份去掉個資的回報(什麼都不會送出),附在 GitHub issue 上即可。 |

## 移除

```sh
aib uninstall                            # 先列出會刪哪些(什麼都不動)
aib uninstall --yes                      # 刪掉這份 aib(一行安裝的);同一台電腦上另一個 aib 不會被動到
aib uninstall --all --yes                # 連 aib 的紀錄與快取一起刪(~/.ez2-aib 會先備份成 ~/ez2-aib-backup-<時間>.tar.gz)
pipx uninstall ez2-aib                   # 用 pipx 裝的話
rm -rf your-project/.aib                 # 只有 `aib ship` 建過、而且你不要了才刪
```

`aib uninstall --yes` 也會拿掉 aib 加進各家 AI 工具設定的掛點(只動 aib 自己的那幾條)、它為那些檔留的 `.bak-…` 備份,
以及桌面上通往你筆記的捷徑。如果 aib 資料夾裡有別的地方都沒有的東西 —— 沒提交的改動、未追蹤的檔、stash、沒推到任何遠端的
commit、別的工作樹 —— 那個資料夾會留著並列出原因;真的要刪才加 `--discard-unsaved-work`。用 `aib ext` 裝的擴充放在 aib 的資料夾裡,
請先用 `aib ext remove <名稱>` 移除。

## 為什麼選擇本地端

如果開發全靠遠端主機或線上平台,只要它們中斷、連不上,所有開發就會完全停擺。
aib 就是在這種情況下誕生的:我們把開發從線上平台搬回自己的電腦,讓紀錄、記憶和進行中的工作都留在本機,
遠端出狀況時,手上的工作照樣能繼續。

AI 本身還是要連到各家的服務;但席位紀錄、人格和記憶都在你的電腦裡,換一家 AI、或等網路恢復,就能從原處接著做。

## 沿革

AIB 的前身是我們 2024 年開始開發的 **ACB**。
ACB 的架構已經不符合現在的使用方式,所以沒有再繼續修補,而是整個重構成 AIB。
`aib test` 和 `aib ship` 是這次重構中開源的核心。
