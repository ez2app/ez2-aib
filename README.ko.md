# aib

**여러 AI가 한 작업 공간에서: 어느 회사의 AI 도구든 무료로 연결하고, 자리마다 고유한 페르소나·전문성·프로젝트 메모리를
부여하며, 갑자기 연결이 끊겨도 어떤 AI든 다른 AI가 하던 일을 그대로 이어받습니다.**

- **어느 회사의 AI든 무료로 연결합니다.** aib는 무료 오픈 소스<sup>[1]</sup>입니다. AI 코딩 도구<sup>[2]</sup>,
  API 키<sup>[3]</sup>로 연결하는 모델<sup>[4]</sup>, 데스크톱 AI 앱(Claude, Codex Desktop, …)을
  모두 자리<sup>[5]</sup>로 열어 함께 일하게 할 수 있습니다. 각 AI는 사용자 본인의 계정이나 키를 쓰며, aib는 별도 요금을 받지 않습니다.
- **aib마다 자기 콕핏<sup>[6]</sup>이 있고, 콕핏마다 자기 자리가 있습니다.** 콕핏은 하나의 tmux<sup>[7]</sup> 창으로,
  여러 AI 자리가 나란히 놓이며 각 자리에는 역할(`dev`, `qa`, `pm`, …)이 있습니다. 자리끼리 메시지를 주고받고 일을 넘깁니다.
- **AI마다 고유한 페르소나와 전문성을 가집니다.** 각 자리는 자기 페르소나<sup>[8]</sup>(첫 번째 두뇌:
  성격, 말투, 일하는 원칙)와 자기 전문성(개발, 테스트, 기획, …)을 가질 수 있습니다.
- **답은 하나가 아닙니다: 서로 다른 회사의 AI가 서로를 검토합니다.** 같은 질문을 서로 다른 회사의 AI에게 맡기면
  각자 답한 뒤 서로 검토하며 약점과 맹점을 짚어 줍니다. 한 회사의 관점에만 갇히지 않습니다.
- **언제든 두 번째 두뇌<sup>[9]</sup>에 기록합니다.** 개발이나 논의 도중 언제든 핵심 내용과 결정을
  두 번째 두뇌(프로젝트 메모리)에 저장할 수 있습니다. 연결이 끊기거나 프로그램이 멈춰도 잃는 것이 없으며, 대화가 길어져
  AI가 혼란스러워하면 자리를 다시 열기만 하면 메모리가 바로 돌아옵니다.
- **어떤 AI든 이어받을 수 있습니다.** 한 자리를 오늘은 Claude로, 내일은 Codex로 돌려도 같은 페르소나와 메모리를 유지합니다.
  대화가 가득 차면 다음 차례를 위해 인수인계 메모를 남깁니다.
- **소중한 대화는 남기고, AI 환각<sup>[10]</sup>은 줄입니다.** 대화에서 남길 만한 내용은 페르소나와 메모리의 후보로
  정제<sup>[11]</sup>되고, 사용자가 승인하면 기록됩니다. 확인할 수 있는 사실이 적혀 있으니 AI가 막연한 기억에 기대어
  추측하는 일이 줄어듭니다.
- **모든 것이 내 컴퓨터에 남습니다.** 자리 기록, 인수인계 메모, 페르소나, 프로젝트 메모리는 모두 사용자 본인의
  컴퓨터(`~/.ez2-aib/`<sup>[12]</sup>)에 저장되며 업로드되지 않습니다.

콕핏은 macOS에서 tmux와 함께 동작합니다. 여러 AI가 하나의 코드베이스를 다루면 변경도 많아지므로, aib에는 단독으로도
쓸 수 있는 안전망이 함께 들어 있습니다(Linux 또는 macOS):

- `aib test`는 변경의 영향을 받는 테스트<sup>[13]</sup>만 다시 실행합니다(Python, bash, Node<sup>[14]</sup>를 추적). 나머지는
  마지막 **그린**<sup>[15]</sup> 결과를 재사용합니다. 레드 결과는 절대 재사용하지 않으며, aib가 측정할 수 없는 것은 항상 실행합니다.
- `aib ship`은 푸시 전 검사<sup>[16]</sup>입니다. 새로운 레드가 없는 패키지만 푸시됩니다. 릴리스는 터미널<sup>[17]</sup> 앞의
  사람만 만들 수 있습니다.

**주**
- [1] 오픈 소스: 코드가 공개되어 있어 누구나 읽고, 쓰고, 고칠 수 있다는 뜻입니다.
- [2] AI 코딩 도구: Claude Code(Anthropic), Codex(OpenAI), Antigravity(Google), GitHub Copilot(GitHub), Grok(xAI) 등 각 회사의 코딩 도우미입니다.
- [3] API 키: AI 서비스가 발급하는 비밀 문자열로, 프로그램이 사용자를 대신해 그 서비스를 호출할 수 있게 해 줍니다.
- [4] API 키로 연결하는 모델: 예를 들어 DeepSeek, OpenRouter(여러 모델로 들어가는 하나의 입구), NVIDIA가 있습니다.
- [5] 자리: 콕핏 안에서 AI 하나가 차지하는 자리로, 자리마다 AI 하나가 자기 역할과 메모리를 가집니다.
- [6] 콕핏: aib가 여는 작업 공간으로, 여러 자리가 나란히 놓입니다.
- [7] tmux: 터미널 창 하나를 여러 칸으로 나누고, 창을 닫아도 계속 실행되게 해 주는 도구입니다.
- [8] 페르소나: 자리의 성격, 말투, 일하는 원칙을 페르소나 카드로 저장한 것으로, 어떤 AI가 그 자리를 열든 불러옵니다.
- [9] 두 번째 두뇌: 자리의 프로젝트 메모리로, 사용자 컴퓨터에 보관되는 메모 모음입니다.
- [10] AI 환각: AI가 틀린 내용을 사실인 것처럼 말하는 현상입니다.
- [11] 정제: 대화에서 남길 만한 내용을 골라 규칙이나 지식으로 정리하는 일입니다.
- [12] `~/.ez2-aib/`: 홈 폴더 안에 있는 폴더로, aib가 기록을 보관하는 곳입니다.
- [13] 테스트: 코드가 여전히 제대로 동작하는지 자동으로 확인하는 작은 프로그램입니다.
- [14] Python, bash, Node: 흔히 쓰이는 세 가지 프로그래밍 언어 / 실행 환경입니다.
- [15] 그린 / 레드: 통과한 테스트는 그린, 실패한 테스트는 레드라고 부릅니다.
- [16] 푸시 전 검사: 코드를 공유 버전(main 브랜치)에 푸시하기 전에 영향을 받는 테스트를 실행하는 것입니다.
- [17] 터미널: 텍스트 명령을 입력하는 창입니다(macOS의 터미널 앱).

## 빠른 시작

```sh
curl -fsSL https://raw.githubusercontent.com/ez2app/ez2-aib/main/install.sh | bash
# ~/ez2-aib에 설치합니다. 언제든 같은 줄을 다시 실행하면 업데이트됩니다(Linux에서는 테스트 안전망만, 콕핏은 macOS 필요)
aib update                                          # aib 설치 후에는 이것도 같은 일을 합니다(aib update --tools는 AI CLI 설치도 제안합니다)
# 다른 방법: pipx install ez2-aib    (pipx가 없다면 macOS: brew install pipx / Linux: python3 -m pip install --user pipx,
#                                     이어서 pipx ensurepath 실행 후 새 터미널 열기)
#            git clone https://github.com/ez2app/ez2-aib ~/ez2-aib && export PATH="$HOME/ez2-aib/bin:$PATH"

cd your-project
aib claude safe dev                  # dev라는 이름의 Claude Code 자리를 엽니다(모든 동작 전에 물어봅니다)
aib codex safe qa                    # 그 옆에 qa라는 이름의 Codex 자리를 엽니다
aib test tests/test_something.py     # 첫 실행: 실행하고 기록합니다
aib test tests/test_something.py     # 변경 없음: 재사용합니다
aib test --all                       # 전체 테스트, 같은 규칙
aib ship package --branch my-branch  # 푸시 전 검사 후 main에 푸시합니다
```

Linux 또는 macOS에서 Python<sup>[18]</sup> 3.9 이상이 필요하며, 콕핏에는 macOS와 tmux가 필요합니다. Windows는 지원하지 않습니다(WSL2<sup>[19]</sup>는 테스트하지 않았습니다).
첫 줄은 한 줄 설치<sup>[20]</sup>이며, 다른 방법은 pipx<sup>[21]</sup>, git<sup>[22]</sup>, PATH<sup>[23]</sup>를 사용합니다.

**주**
- [18] Python: 프로그래밍 언어의 하나로, aib가 이 언어로 작성되었으므로 먼저 설치되어 있어야 합니다.
- [19] WSL2: Windows 안에서 Linux를 실행하는 Windows 기능입니다.
- [20] 한 줄 설치: `curl … | bash`는 설치 프로그램을 내려받아 곧바로 실행합니다.
- [21] pipx: Python 명령줄 도구를 설치하되 도구마다 서로 분리해 두는 도구입니다.
- [22] git: 코드의 모든 변경을 기록하는 도구이며, `git clone`은 전체 사본을 내려받습니다.
- [23] PATH: 컴퓨터가 명령을 찾는 폴더 목록으로, 폴더를 추가하면 `aib`를 입력해 실행할 수 있습니다.

## 콕핏: 여러 AI를 나란히

**콕핏**은 여러 AI 코딩 도우미("자리")를 하나의 tmux 창에 나란히 실행합니다. 각 자리에는
역할(`dev`, `qa`, `pm`, …)이 있으며, 좌 / 중 / 우 레이아웃, 마우스 메뉴, 자리 간 메시지, 대화가 가득 찰 때의
인수인계 메모, 그리고 플릿 도구<sup>[24]</sup>(자리 신원, 작업 배분, 순찰)를 제공합니다.

```sh
aib claude safe dev        # dev라는 이름의 Claude Code 자리를 열고, 모든 동작 전에 물어봅니다
aib codex dgrs qa          # qa라는 이름의 Codex 자리를 모두 허용 모드로 엽니다(아래 참고)
aib --help-cockpit         # 모든 옵션
```

- **요구 사항:** macOS와 tmux. 각 AI의 명령줄 도구<sup>[25]</sup>가 미리 설치되어 있고 로그인되어 있어야 합니다
  (`claude`, `codex`, `grok`, …). aib가 대신 설치하거나 로그인해 주지 않습니다. 콕핏은 아직 Linux에서 시험해 보지 않았습니다.
- **macOS에서의 bash 테스트:** aib는 bash 4.1 이상으로 bash 스크립트를 추적합니다. macOS에는 bash 3.2가 들어 있으므로, bash 스크립트를 실행하는 테스트는
  "측정 불가"로 보고되어 항상 다시 실행됩니다(안전하지만 느릴 뿐입니다). `brew install bash`<sup>[26]</sup>를 하면 재사용할 수 있게 됩니다.
- **자리별 권한 모드:** `safe`는 AI 도구의 기본 보호 장치를 유지합니다(파일을 수정하거나 명령을 실행하기 전에 물어봅니다).
  `dgrs`는 이 보호 장치를 **해당 자리에서만** 끄므로 AI가 묻지 않고 실행합니다. 이때 aib는 경고와 함께 그 자리를
  `safe`로 다시 여는 명령을 출력합니다. 자리를 열 때마다 자리별로 선택합니다.
- **Claude**는 Anthropic의 상표이고, Codex는 OpenAI, Grok은 xAI의 상표입니다. aib는 이들 회사와 관련이 없습니다.

**주**
- [24] 플릿 도구: 여러 자리를 한꺼번에 관리하는 기능으로, 각 자리가 누구인지, 작업 배분, 정기 순찰 등을 다룹니다.
- [25] 명령줄 도구: 터미널에서 명령을 입력해 사용하는 프로그램입니다(예: `claude`, `codex`).
- [26] `brew install bash`: macOS에서 소프트웨어를 설치하는 일반적인 방법인 Homebrew로 최신 bash를 설치합니다.

## 계획 중: 여러 컴퓨터와 소셜 채널로

> 아래 기능은 계획 단계이며 아직 사용할 수 없습니다. 각 기능이 완성되면 CHANGELOG<sup>[27]</sup>에 기록합니다.

- **서로 다른 컴퓨터의 AI가 대화합니다.** 모든 AI를 한 컴퓨터에 몰아넣을 필요 없이, 집, 회사,
  클라우드 호스트<sup>[28]</sup>에 있는 AI 자리끼리 메시지를 주고받을 수 있습니다.
- **내 컴퓨터에서 다른 컴퓨터의 aib를 조작합니다.** 내 컴퓨터의 aib에서 대화를 통해 다른 컴퓨터의 aib 콕핏을 조작하거나,
  그 호스트의 aib에 명령을 보냅니다.
- **소셜 대화 관리.** LINE, Telegram 등 소셜 플랫폼의 대화를 가져와 관리합니다. LINE과 Telegram은 이미 내부 테스트에서
  동작하며, 추후 공개할 예정입니다.

**주**
- [27] CHANGELOG: 각 버전에서 무엇이 추가되거나 바뀌었는지 적은 기록입니다.
- [28] 호스트: 프로그램을 실행하는 컴퓨터로, 노트북, 사무실 컴퓨터, 임대한 클라우드 서버 등이 있습니다.

## 개발 중: 더 빠른 테스트

> 이 부분은 아직 개발 중이며, 아래 수치와 동작은 바뀔 수 있습니다.

aib는 각 테스트가 어떤 파일을 읽었는지 기억해 두고, 다음에는 변경의 영향을 받는 테스트만 다시 실행하며 나머지는 마지막 그린
결과를 재사용합니다.

**실측: aib 자체 개발 기록**(2026-10-08 ~ 10-10, 푸시<sup>[29]</sup> 28회, 회당 약 1,020개 테스트)

| 테스트 실행 방식 | 28회 푸시 합계 | 푸시당 평균 | 하나씩 실행 대비 절감 |
|---|---|---|---|
| aib 없이, 테스트를 하나씩<sup>[30]</sup> | 91.1시간(약 3.8일<sup>[31]</sup>) | 195분 | (기준) 91.1시간 |
| aib 사용, 같은 프로젝트를 한 번에 실행<sup>[32]</sup> | 43.8시간(약 1.8일) | 94분 | 47.3시간 절감(약 2일, 52%) |
| **aib 사용, 같은 프로젝트를 3개로 나눠 실행** | **16.6시간(약 0.7일)** | **36분** | **74.5시간 절감(약 3.1일)** |

- 91.1시간에서 43.8시간으로 줄어든 것은 aib의 재사용<sup>[33]</sup> 덕분입니다. 변경의 영향을 받지 않는 테스트는 다시 실행하지 않습니다. 16.6시간까지 줄어든 것은 남은 테스트를 3개로 나눠 동시에 실행했기 때문입니다.
- 36분은 이 28회 푸시의 평균이며, 기록이 쌓인 뒤 마지막 10회 푸시의 평균은 약 18분이었습니다.
- 재사용이 틀린 적은 없을까요? 재사용된 테스트 13개를 무작위로 골라 실제로 다시 실행한 결과, 13개 모두 같은 결과였고 잘못 재사용된 것은 0개였습니다.

| 프로젝트 | pytest<sup>[35]</sup> 병렬 실행 | aib 첫 실행 | 이후 실행마다 절감 |
|---|---|---|---|
| [attrs](https://github.com/python-attrs/attrs)<sup>[36]</sup>(테스트 26개) | 8.2초 | 15.1초 | 약 5초(변경이 없으면 3.0초) |
| [click](https://github.com/pallets/click)<sup>[37]</sup>(테스트 43개) | 6.2초 | 17.2초 | 약 2초(변경이 없으면 3.8초) |

- 첫 실행에서는 각 테스트가 읽은 파일을 기록하므로 pytest보다 느립니다. 두 번째 실행부터는 영향을 받지 않는 테스트를 재사용합니다.
- "이후 실행마다 절감"은 변경이 없다고 가정한 값입니다. 변경이 건드리는 파일이 많을수록 다시 실행하는 테스트가 늘고 절감은 줄어듭니다.
- **잘 맞는 경우:** 전체 실행에 몇 분 이상 걸리고, 변경할 때마다 그중 일부만 건드리는 테스트 모음. **잘 맞지 않는 경우:** 몇 초 만에 끝나는 테스트 모음.
- 부수 효과로, 각 테스트를 따로 실행하므로 다른 테스트가 먼저 실행되어야만 통과하는 테스트가 드러납니다.

**주**
- [29] 푸시: 완성한 변경을 모두가 공유하는 버전으로 보내는 일입니다.
- [30] 테스트를 하나씩: 91.1시간은 aib 아래에서 측정한 각 테스트 시간을 더한 추정치로, 추적 오버헤드가 포함되어 있어 실제보다 높게 나옵니다.
- [31] 일: 24시간을 1일로 계산했습니다(AI는 쉬지 않고 실행할 수 있기 때문입니다).
- [32] 한 번에 실행: aib가 영향을 받는 테스트만 하나씩 차례로 실행하는 방식이며, 43.8시간은 그 테스트들의 실제 실행 시간을 합한 값입니다.
- [33] 재사용: 테스트가 읽은 파일이 하나도 바뀌지 않았으면 다시 실행하지 않고 마지막 그린 결과를 그대로 쓰는 것입니다.
- [34] 월간 예상 절감: 실측 기간의 속도(주당 약 28회, 월 약 121회 푸시)에 × 52 ÷ 12를 적용해 추산한 값으로, 푸시가 적으면 절감도 줄어듭니다. 푸시 한 번마다 하나씩 실행할 때보다 약 160분을 절감하며, 그중 약 101분은 aib의 재사용 덕분입니다.
- [35] pytest: 가장 널리 쓰이는 Python 테스트 도구로, 모든 테스트를 실행하고 어떤 테스트가 통과했는지 알려 주며, "병렬 실행"은 여러 프로세스를 동시에 돌리는 가장 빠른 방식입니다.
- [36] attrs: 프로그래머가 반복적인 코드를 쓰지 않도록 도와주는 잘 알려진 오픈 소스 Python 패키지입니다.
- [37] click: 명령줄 도구를 만드는 데 쓰는 잘 알려진 오픈 소스 Python 패키지입니다.

## 지원 언어

Python(unittest<sup>[38]</sup>, pytest)은 완전히 추적합니다. Node(node:test, jest, mocha<sup>[39]</sup>), Go, PHP<sup>[40]</sup>는
aib를 통해 실행되며 푸시 전 검사를 받습니다. 얼마나 재사용할 수 있는지는 추적기가 무엇을 볼 수 있느냐에 달려 있으며, 현재 표는
`docs/AIB-TEST-QUICKSTART.ko.md`를 참고하십시오.
다른 언어는 `.aib/ship.toml`에 테스트 명령을 선언할 수 있습니다. 이 경우 항상 실행되지만 패키징과 릴리스는 동작합니다.

**주**
- [38] unittest: Python에 기본으로 들어 있는 테스트 도구입니다.
- [39] node:test, jest, mocha: Node에서 흔히 쓰이는 세 가지 테스트 도구입니다.
- [40] Go, PHP: 또 다른 두 가지 프로그래밍 언어입니다.

## 재사용은 얼마나 안전한가요?

- 그린 결과만 재사용하며, 그것도 테스트가 읽은 모든 입력이 바이트 단위로 동일할 때만 재사용합니다.
- aib가 테스트가 무엇을 읽었는지 볼 수 없으면(추적할 수 없는 하위 프로세스<sup>[41]</sup>, 네트워크, 스스로 파일을 읽는 것으로 알려진 네이티브 확장),
  그 테스트는 측정 불가로 표시되어 항상 실행됩니다.
- **알려진 빈틈:** aib의 목록에 *없으면서* C 코드에서 파일을 읽는 C 확장<sup>[42]</sup>은 Python의
  감사 훅<sup>[43]</sup>에 보이지 않습니다. Linux에서는 아래의 네이티브 안전망이 이를 잡아내지만, **안전망이 없으면(macOS, 또는 C 컴파일러<sup>[44]</sup>가 없는 경우)
  그런 파일이 바뀌어도 다시 실행되지 않을 수 있습니다.** 테스트가 그런 방식으로 읽는 파일에 의존한다면, 릴리스 전에 `aib test --fresh`를
  실행하십시오.
- `aib ship audit`은 재사용된 테스트 중 무작위 표본을 다시 실행해 결과를 비교합니다.

**주**
- [41] 하위 프로세스: 실행 중인 프로그램이 따로 띄우는 프로그램입니다.
- [42] C 확장: Python이 호출하는 C로 작성된 구성 요소로, 빠르지만 그것이 읽는 파일을 Python이 볼 수 없습니다.
- [43] 감사 훅: Python에 내장된 "파일이 열리면 알려 달라"는 장치로, aib는 이를 이용해 테스트가 읽은 파일을 기록합니다.
- [44] C 컴파일러: C 소스 코드를 실행 가능한 프로그램으로 바꾸는 도구입니다(예: `cc`, `gcc`, `clang`).

## 개인정보

aib는 사용자의 코드, 테스트 결과, 그 밖의 어떤 것도 저희에게 보내지 않습니다. 기록은 사용자 컴퓨터에만 남습니다
(`~/.ez2-aib/`, 그리고 `~/.cache/ez2-aib/`의 작은 캐시). aib 자체의 네트워크 통신은 `aib ship`이 git으로 하는 일,
즉 **사용자 본인의** 원격 저장소<sup>[45]</sup>에서 fetch하고 push하는 것뿐입니다.

콕핏은 한 가지 점에서 다릅니다. 사용자가 여는 AI 자리는 각 AI 회사의 자체 도구이며, 평소처럼 해당 회사와 통신합니다.
콕핏 자체가 사용자 컴퓨터에 보관하는 것은 모두 `~/.ez2-aib/` 아래에 있습니다.
자리 기록과 인수인계 메모, 자리 간 메시지, 프로젝트 카드와 역할 카드, 그리고 API 키 자리에 추가한 API 키
(`~/.ez2-aib/secrets/`에 저장, 폴더 0700 / 파일 0600<sup>[46]</sup>, 옆에 저장된 키로 암호화 — 이는 우연히 들여다보거나
실수로 커밋하는 것을 막을 뿐, 이미 사용자의 홈 폴더를 읽을 수 있는 사람까지 막지는 못합니다). `~/.ez2-aib/`를 삭제하면 모두 지워집니다.

**주**
- [45] 원격 저장소(fetch / push): 온라인에 보관된 코드 사본(예: GitHub)으로, fetch는 거기서 내려받고 push는 거기로 올립니다.
- [46] 0700 / 0600: 사용자 본인의 계정만 읽고 쓸 수 있다는 뜻의 파일 권한입니다.

## 네이티브 안전망(Linux 전용)

일부 테스트는 C 코드(네이티브 확장, C 라이브러리)에서 파일을 읽으며, Python의 감사 훅은 이를 볼 수 없습니다.
Linux에서 PATH에 C 컴파일러(`cc`, `gcc` 또는 `clang`)가 있으면, aib는 함께 제공되는 작은 C 파일
(`aib/tools/verify/ldp-shim/`)을 `~/.cache/ez2-aib/`에 컴파일하고 **테스트 프로세스에만** 미리 로드(`LD_PRELOAD`<sup>[47]</sup>)하여
이런 읽기도 기록합니다. 컴파일러가 없거나 라이브러리를 로드할 수 없으면 안전망은 꺼진 채로 남고,
aib가 그 이유를 알려 줍니다. **이 경우 위에서 설명한 빈틈이 열려 있습니다.** C 코드에서 일어난 읽기는 기록되지 않으므로, 그런 파일이 바뀌어도
테스트가 다시 실행되지 않을 수 있습니다. macOS에서는 사용할 수 없습니다.
`AIB_NATIVE_GUARD=0`으로 끌 수 있습니다.

**주**
- [47] `LD_PRELOAD`: 프로그램이 시작될 때 작은 구성 요소를 먼저 불러오게 하는 Linux 기능으로, aib는 이를 이용해 C에서 일어난 읽기를 기록합니다.

## 임시 폴더를 깨끗하게

테스트는 종종 임시 파일을 남기고, 때로는 백그라운드 프로그램까지 남깁니다(테스트가 끄는 것을 잊은 tmux 서버는 몇 시간씩
실행되며 수 기가바이트의 메모리를 차지할 수 있습니다). aib는 자신이 실행한 테스트의 뒷정리를 합니다.

- 각 테스트는 자기만의 임시 폴더(`TMPDIR`<sup>[48]</sup>, `<tmp>/aibt-…` 아래)를 받으며, 테스트가 끝나면 삭제됩니다.
- 테스트가 시작해 놓고 계속 실행 중인 백그라운드 프로그램은 테스트가 끝날 때 중지됩니다.
- 요약에 무언가를 남긴 테스트의 이름이 표시되므로, 원인을 직접 고칠 수 있습니다.
- `aib tmp`는 aib와 그 테스트가 임시 폴더에 남긴 것, 그리고 이미 끝난 테스트가 남긴 백그라운드 프로그램을
  보여 줍니다. `aib tmp --apply`는 이를 제거합니다. aib의 것이 아닌 것, 심볼릭 링크, 실행 중인 프로그램이 아직 사용하는 것은
  절대 건드리지 않습니다. `aib ship`은 푸시 전 검사 전에 이 작업을 자동으로 수행합니다.

**주**
- [48] `TMPDIR`: 프로그램에 임시 파일을 어디에 둘지 알려 주는 설정입니다.

## CI

`aib ship ci`는 aib의 기록을 Actions 캐시에 보관하는 GitHub Actions<sup>[49]</sup> 워크플로<sup>[50]</sup>를 작성하므로, CI<sup>[51]</sup>에서도
변경된 것만 실행합니다. 포크<sup>[53]</sup>에서 온 풀 리퀘스트<sup>[52]</sup>는 항상 전부 실행합니다(이들이 기록을 건드릴 수 없어야 하기 때문입니다).

**주**
- [49] GitHub Actions: GitHub의 자동화 서비스로, 코드를 푸시하면 테스트를 자동으로 실행합니다.
- [50] 워크플로: 실행할 단계를 나열한 GitHub Actions용 설정 파일입니다.
- [51] CI(지속적 통합): 누군가 코드를 푸시할 때마다 클라우드에서 테스트를 자동으로 실행하는 것입니다.
- [52] 풀 리퀘스트(PR): 프로젝트 소유자에게 내 변경을 병합해 달라고 요청하는 것입니다.
- [53] 포크: 다른 사람이 자기 계정 아래에 만든 내 프로젝트의 사본입니다.

## 제거

```sh
aib uninstall                            # 삭제될 항목을 먼저 보여 줍니다(아무것도 바꾸지 않음)
aib uninstall --yes                      # 이 aib(한 줄 설치)를 삭제합니다. 같은 컴퓨터의 다른 aib는 건드리지 않습니다
aib uninstall --all --yes                # aib의 기록과 캐시도 삭제합니다(~/.ez2-aib는 먼저 ~/ez2-aib-backup-<시각>.tar.gz로 백업)
pipx uninstall ez2-aib                   # pipx로 설치한 경우
rm -rf your-project/.aib                 # `aib ship`이 만들었고 더 이상 필요 없을 때만
```

## 왜 로컬 우선인가

모든 개발이 원격 호스트나 온라인 플랫폼에 의존한다면, 그것이 중단되거나 연결할 수 없게 되는 순간 모든 것이 멈춥니다.
aib는 바로 그런 상황에서 탄생했습니다. 저희는 개발을 온라인 플랫폼에서 다시 자기 컴퓨터로 옮겨,
기록, 메모리, 진행 중인 작업이 로컬 컴퓨터에 남아 원격에 문제가 생겨도 계속 진행되도록 했습니다.

AI 자체는 여전히 각 회사의 서비스에 연결하지만, 자리 기록, 페르소나, 메모리는 사용자 컴퓨터에 있습니다.
다른 회사의 AI로 바꾸거나 네트워크가 돌아오기를 기다렸다가, 멈췄던 곳에서 바로 이어서 작업할 수 있습니다.

## 연혁

AIB는 저희가 2024년에 개발을 시작한 **ACB**의 후속작입니다.
ACB의 구조가 지금의 사용 방식에 더 이상 맞지 않아, 계속 손보는 대신 AIB로 처음부터 다시 만들었습니다.
`aib test`와 `aib ship`은 이 재구축에서 오픈 소스로 공개한 핵심입니다.
